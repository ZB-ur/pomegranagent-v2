# V2：让孩子愿意说，也说得完

## 已确认的方向

- 独立开发，第一优先为儿童自然交流并形成忠实记录。
- 用电脑；教师可在旁协助，儿童也可能独立操作，不能依赖阅读说明。
- 首期支持 macOS 与 Windows；两端都需能完成教师准备、幼儿听说交流及记录留存的完整流程。
- 每一步都有语音提示和引导；空格键切换语音输入启停。
- 暖色视觉；常驻、有状态动作的 IP。参考 V1 白鸭、黑色圆框眼镜、橙色嘴脚、暖黄色日记本。采用 2D 绘本风格简化实现。
- 首版围绕教师本地使用，不继承旧平台流程或旧版全部功能。
- 首期包含教师端幼儿管理、排班管理、小鸭管理；AI 打分及相关成长评价延后。
- 教师端“今天”汇总页延后，首期默认进入排班日历；保留日历内回到今天的定位按钮。
- 儿童端与教师端交互原型已获用户确认；后续以此作为正式开发的体验基线，不重启整轮交互探索，具体实现与局部细节可自主优化。

## 第一条路径

教师安排当天一至多名幼儿 → 儿童在今日名单用大头像选择自己 → 鸭鸭欢迎并说明怎么操作 → 儿童按空格开始说 → 再按空格结束这次输入 → 鸭鸭回应并引导继续 → 儿童点小本子结束聊天 → 朗读、核对和必要修正 → 保存并能再次找到。

空格控制的是一段语音输入，结束聊天是另一个明确动作。孩子停顿时不自动结束。一次已经说清楚可以结束，不要求固定问卷或三轮对话。

儿童成功标准：不靠读字也知道什么时候说、怎么停止、是否记好了。教师成功标准：需要协助少，记录忠实，之后找得到。

### AI 回应与引导

首期必须包含真实 AI 对话：幼儿按空格结束一段发言后，系统根据本次语音输入的实际内容与当前幼儿的对话上下文理解和回应，再用中文语音播出。可采用语音识别、对话模型、语音合成组合，也可选合适的语音模型；实现方式不冻结。

回应要简短、贴合刚才的内容。需要补充时一次最多问一个具体、易懂、开放的问题；内容不清楚时温和确认，不替幼儿编造观察、感受或原因，默认最多 3 轮，教师可配置轮数。幼儿可以补充、纠正、重听或结束，结束后不继续追问。AI 的话与幼儿原话分开保存，不能把 AI 提出的内容当成幼儿已表达的事实。

操作引导与内容对话分别实现：例如“按空格开始说”可使用固定提示；对幼儿经历的接话必须来自真实 AI 对当前输入的理解。验收时用不同内容、补充和纠正的真实发言，检查回应是否随内容变化、上下文是否连贯、是否尊重结束意愿。当前原型的固定接话不算该能力已交付。

### macOS 与 Windows 支持

两端均为首期交付目标，覆盖安装或启动、设备权限、中文语音输入与播音、键盘焦点及快捷键、幼儿与小鸭管理、排班、记录保存与重启找回、导出和备份恢复。选型时处理路径、启动命令和设备能力差异，不依赖某一系统独有能力完成核心路径。本地使用不代表语音与 AI 必须离线。

具体最低系统版本、CPU 架构和浏览器范围结合目标设备明确，并写入运行说明；不默认承诺所有历史系统与浏览器。两端分别实机验收并记录系统、浏览器或运行环境版本，尤其核对麦克风权限、实际听说及键盘操作。只有 macOS 的结果不能证明 Windows 已通过；当前尚无双系统完整验收证据，无法访问的设备保留待验收状态。

## 当前交互选择

左侧常驻小鸭，右侧当前话语和大操作按钮。听的时候侧耳轻摆；说话时使用开口姿态并随播音轻动；保存后开心跃动；空闲时轻微呼吸。尊重系统减少动态效果设置。

以声音引导为主，大图标和简短文字辅助。记录提供朗读。首次播音受浏览器自动播放规则限制，因此小鸭本身也是始终可见的重听入口。教师负责首次设备权限与声音检查。

应用播音和语音输入不同时进行。先播启动提示，再打开输入；输入过程中不插话。浏览器识别服务因为停顿结束一个会话时继续等待或重启识别，只有显式停止才提交。已经识别出的文字及时保存为草稿。

### 幼儿端语音引导验收

语音引导属于首期必需能力，随每条交互路径一起实现。这里的“每一步”指儿童需要理解的新状态或行动，不要求对每次焦点变化排队播放完整说明。

| 状态 | 儿童应该听懂什么 |
| --- | --- |
| 进入与选人 | 如何选自己的大头像、当前选中的是谁、如何确认；名单为空时如何请老师帮助。 |
| 进入对话或恢复草稿 | 鸭鸭知道自己是谁、接着聊什么，以及下一步按哪个键。 |
| 准备与录入 | 开始前说明操作；输入真正就绪时给清晰反馈；说完再按空格，思考停顿不算结束。录入过程中不播会被麦克风收进来的说明。 |
| 停止与等待 | 已经停止收音，系统正在处理；等待较长时有简短提示，不用技术术语或虚假的进度数字。 |
| 回应与继续 | 回应刚才说的内容，一次只给一个易懂的问题；能继续、重听或主动结束，默认最多 3 轮，可由教师配置。 |
| 核对、保存与换人 | 能朗读记录，知道如何补充和保存；只有保存成功才说“记好了”，随后提示下一位如何开始。 |
| 失败与重试 | 用儿童能理解的话说明下一步，已识别内容保留；语音输出本身不可用时，以醒目的视觉反馈引导教师协助，不能仍声称可独立完成。 |

新提示取代过时提示；快速移动头像焦点时只播最终选择，避免积压。允许重听，不反复强制播放已经熟悉的长教程。语音的内容、时机、屏幕状态和小鸭动作一致；声音优先清晰自然，语速和停顿需在目标设备上听验。

首期不新增单测，不建立自动测试体系。验收分开记录：Astra Computer Use 在实际应用中验证键盘、焦点、状态和流程；用户通过真实扬声器、麦克风与服务验证听说效果；儿童试用验证是否理解、是否需要教师反复提醒。必要时用日志协助定位，但仅有 TTS 调用或播放回调不等于充分的语音引导。

记录以原话为依据，不补写儿童没表达的行动、原因、情绪或能力评价。允许教师修正，同时保留原始对话。记录整理质量与对话质量分别验证。

## 原型实现与限制（历史基线）

默认示例模式不录音，用虚构样例演示交互。可选浏览器麦克风模式采集实际发言并转文字，但接话仍是固定引导，尚未接入对话 AI。语音提示与记录朗读使用设备中文语音。真实输入的服务可能联网，不能承诺本地离线。

记录保存在当前浏览器，原型已按幼儿关联草稿和记录；正式幼儿档案、数据库、可靠备份和模型接入尚未实现，属于首期交付要补齐的能力。示例模式的通过不等于真实儿童语音体验通过。

## 接下来用真实体验决定

在目标电脑上以成人测试先确认：中文引导能听清、空格操作可靠、思考停顿不误提交、麦克风不会识别自己的播音、识别失败后已说内容还在。再观察儿童需要多少次协助，改进语速、措辞和反馈。

确定应用内 AI 服务后，用少量代表性对话验证：是否回应刚才的内容、追问是否自然、记录是否编造、儿童结束后是否还纠缠追问。Astra 是开发模型，不自动成为应用内模型。

操作系统目标已明确为 macOS 与 Windows；具体系统版本、CPU 架构和浏览器、年龄范围、麦克风条件、应用模型与正式记录形式仍待明确。当前原型不冻结正式技术栈。

## 范围与开发方式

幼儿管理、排班管理、小鸭管理是首期必要准备，不能停留在示例切换器。暂不安排 PIN、多角色权限、自动轮班优化、成长评分和分析图表。新功能应能解释它帮助核心路径中的哪件事。

主智能体保持产品与实现的连续上下文；有独立问题时根据收益使用已授权的协作。项目目前不增加自定义 skill。按风险验证，完成意味着实际操作并修复阻塞；模型效果用可用性、体验、人工返工、耗时和成本评价。

## 首期交付范围

已确认包含上述三个管理模块，AI 打分延后。以下为模块细节与验收建议。管理模块已有浏览器操作原型，正式交付仍需真实服务与存储；界面和技术栈没有冻结。

目标：教师在一台电脑上准备名单、小鸭资料和排班，幼儿依次自然交流，教师能核对、留存和找回真实记录。

| 模块 | 首期建议交付 |
| --- | --- |
| 幼儿管理 | 新增、编辑姓名与小名，上传和裁切照片；离班后归档，历史记录保留。 |
| 小鸭管理 | 管理实际饲养的小鸭：名字、照片、简短特征与教师备注；不再饲养时归档，历史记录保留。实际小鸭档案与常驻陪伴 IP 分开。 |
| 排班管理 | 按日期安排一至多名幼儿；以完整月历总览，点日期编辑当天名单，支持日期定位和按周复用安排；今日名单直接驱动儿童入口，展示待交流、进行中、已记录。无需复杂时段或自动轮班算法。 |
| 儿童交流 | 大头像选择、完整键盘操作、逐步语音引导、常驻动态 IP；真实语音输入与 AI 接话，可停顿、补充、结束和恢复草稿。 |
| 记录与教师核对 | 保留原始对话，生成忠实记录；教师查看、修改与确认，按幼儿和日期查找。明确提到的小鸭可关联；不确定时不强行归属。 |
| 本地使用 | 简便启动与设备检查，正式持久化，基础导出和可恢复的备份；重启后档案、排班和记录仍可用。联网语音与模型服务在设置中说明。 |

教师端以排班日历为默认入口，直接选日期、安排幼儿并进入儿童端。幼儿、小鸭与故事记录通过侧栏进入；记录核对在故事记录中完成。“今天”汇总工作台留待后续版本。

AI 首期负责自然接话与忠实整理；不做能力打分、发展等级、排名、成长曲线、自动教育评价或周期分析报告。暂不扩展家长端、多园所、多角色账号、云端同步、移动端适配和复杂 3D 动画系统。

交付验收围绕真实使用：教师从空数据建好幼儿和小鸭、安排当天多人；儿童仅靠键盘依次完成真实语音交流，身份和草稿不串；儿童停顿或服务失败时已识别内容保留且可继续；教师能核对修正记录，重启后找回；备份实际恢复成功。由 Astra Computer Use 操作实际应用，并结合用户目标设备上的语音、真实 AI 与儿童使用反馈验收。模拟演示不能替代真实验证。日常修复只复查受影响路径及关联行为，可交付阶段再完整走查。

推进建议：先把“教师准备 → 今日名单 → 一名幼儿真实交流 → 教师核对保存”做成可运行的完整路径，再扩展多人轮换、近期排班和资料维护，最后完成真实设备试用与备份恢复验证。每段都能实际操作，不先堆齐管理页面后才接语音和 AI。

## 今日排班与身份选择

教师准备：设置日期、选择当天一至多名幼儿，每名幼儿有稳定的头像/照片和姓名。正式使用优先采用教师提供的真实照片，保持面部清晰、裁切统一，不靠姓名首字或每次变化的图片辨认身份。原型以虚构插画起步，教师端现可上传照片并保存排班，数据仍只在当前浏览器中。照片提供居中显示与预览，手动裁切待后续实现。

儿童入口只展示当天名单。电脑端三个示例头像约 170×170 像素，卡片有明显的键盘焦点；一人仍展示头像，供孩子确认身份。多人时用方向键选头像，读出焦点幼儿姓名，回车进入其对话。更多人保持头像尺寸，必要时换行滚动，不压成小图标。

对话中显示当前幼儿的小头像与姓名。草稿按幼儿分别保存，重新选中可继续；记录保存时写入同一幼儿身份。保存后回到今日名单，标记“今天已记好”，优先把焦点移到下一位尚未完成的幼儿。完成的幼儿仍可再选自己补充，不做权限锁。

键盘：方向键选择头像或当前页面操作；回车执行；空格在对话页专用于语音启停；Esc 返回（录音中先停止并保留文字，再按返回）；F1 重听步骤；Tab/Shift+Tab 保留标准导航。编辑文字时保留原生键盘行为。

独立儿童演示保留 1、3、4 人的示例切换；从教师工作台进入时，改用已保存的对应日期名单。已通过浏览器纯键盘操作确认：选择朵朵 → 输入 → 暂离 → 选择沐沐时不显示朵朵的内容 → 返回朵朵恢复草稿 → 查看/保存记录 → 回到名单出现完成标记。

- [Microsoft Shifts 排班复用](https://support.microsoft.com/en-us/teams/shifts/copy-a-schedule-in-shifts)：已有排班复制后再调整。这里提供沿用上周同日名单和整周复制，复制前显示填入/保留天数，已有安排不覆盖。
- [Brightwheel 幼儿档案](https://help.mybrightwheel.com/en/articles/942377-add-students)：档案集中入口、明确新增动作、照片与基本资料。这里保留姓名、小名、头像、教师备注，不扩展家庭联系人、收费和角色体系。

本项目的设计判断：月历负责全局、常驻侧栏负责当天编辑，减少来回开关弹窗；在 1280×720 电脑上完整显示月份，包括六周的月份。多人勾选后统一保存，未保存离开时可以继续编辑、放弃或保存后继续。日期单元最多显示两个姓名并标出总人数，详情侧栏显示全部候选幼儿；只靠颜色不能表达完成状态，因此已记录同时带勾选标记。

教师端沿用米白、暖黄与鼠尾草绿，小鸭 IP 作为轻量陪伴；幼儿与实际小鸭资料用照片卡片辨认。默认进入排班日历，管理模块与故事核对通过侧栏到达；“今天”汇总页已按用户要求移除，延后再考虑。原型功能与验证边界以 README 为准，尚不代表正式交付已完成。


## 小鸭头像方案

建议实际小鸭以教师上传的真实照片为主，优先展示清晰的头部与可辨认羽毛特征，图片旁始终保留名字。外形相近时，照片配合教师填写的特征辨认，不依赖系统生成的不同外貌来区分。聊天陪伴 IP 使用统一绘本形象，不随实际小鸭照片变化。

当前原型：三只示例小鸭使用代码绘制的 SVG 插画，支持教师上传、预览、替换和移除照片，并在当前浏览器保存；显示时居中适配，尚无手动裁切。未上传照片的新档案使用统一占位插画。

正式实现建议：选照片 → 在方形取景框内拖动、缩放并预览 → 保存；派生卡片与小头像两种尺寸，图片存入应用本地资料目录，随档案一起备份。首期不加入 AI 自动识别小鸭或照片转卡通，以保留真实外观并减少教师准备成本。这部分为头像实现建议，裁切与文件存储尚未实现。

## 正式开发中的技术决定（2026-09-08）

正式应用保留原型素材与体验结构，使用 Python 标准库本机服务、SQLite、原生浏览器模块；正式文件与 `prototype/` 分开。数据库作为正式资料来源，按 revision 防止多窗口覆盖。儿童录音用 MediaRecorder 显式启停，停顿不提交；结束后识别、真实模型接话、真实语音播出，对话供应商已由用户确定为 DeepSeek，识别与播音经用户确认采用本机 SenseVoice Small int8 与 Kokoro v1.1 zh（sherpa-onnx CPU + PyAV，Python 3.12 项目虚拟环境）；录音不离开本机，只有对话文字发给 DeepSeek。选择记录本才进入整理与核对，AI整理失败保留逐字原话；原始幼儿与AI发言分开保存，教师核对不覆盖原始对话。

照片在方形取景框裁切后保存到 SQLite，随备份带走；不单独维护图片目录，避免数据库与文件复制不同步。暂存未识别录音目前保留于原浏览器，不能据此宣称音频迁移/断电恢复已完成。儿童入口仅使用当前电脑今天的安排。拟支持范围、运行入口、实际验收与待验收项统一维护在 README。

## 单次对话轮数（2026-09-08 用户确认）

默认 3 轮，教师在设备、服务与备份中配置 1–20 轮；幼儿一段成功识别的发言与鸭鸭一次回复构成一轮，开场引导不计轮数，失败重试不增加轮数。每次新建草稿记住当前设置，恢复时沿用。最后一轮先由真实 AI 根据内容正常回应且不再提问，再追加固定结束语：“今天先聊到这里吧。我们一起听听你的故事，再把它记下来。”固定结束语作为鸭鸭发言与回复一同保存，播完进入整理核对，不再开始下一轮。幼儿可提前结束；到达上限后在核对区由教师帮助修改。此决定替代此前不限轮数的约定。

回应等待与播读（2026-09-08 确认）：等待阶段提供小鸭动效与状态反馈，保护键盘及相关操作免于误触；语音回应按实际播出的句子同步显示文字，播完再开放下一步，末轮固定结束语播完后进入核对。
